# wsl-windows-relocate

WSL上のフォルダの実体をWindows側のファイルシステム（`/mnt/c/...`）に移動し、元の場所からシンボリックリンクで参照できるようにする。

## 手順

### Step 1: パスの確認

ユーザーから以下を確認する（すでにメッセージ内で指定されていれば聞き直さない）。

- 移動元（WSL側の現在のパス）
- 移動先（Windowsパス形式 `C:\Users\...` またはWSL形式 `/mnt/c/Users/...` のどちらでもよいが、`C:\` 形式で渡された場合は `/mnt/c/...` 形式に変換して扱う）

移動先・移動元は環境（Windowsユーザー名やドライブ構成）によって異なるため、**ハードコードせず必ずその場でユーザーから受け取ったパスを使う**こと。

### Step 2: 事前確認

```bash
ls -la <移動元>
ls -la <移動先の親ディレクトリ>  # 存在しなければ mkdir -p する
```

- 移動元がGitリポジトリかどうか（`.git`ディレクトリの有無）を確認する
- 移動先に同名のディレクトリが既に存在する場合は、上書きせずユーザーに確認する

### Step 3: 移動とシンボリックリンク作成

```bash
mkdir -p <移動先の親ディレクトリ>
mv <移動元> <移動先>
ln -s <移動先> <移動元>
```

### Step 4: Gitリポジトリの場合の後処理

移動元が Git リポジトリだった場合、DrvFs（Windows側マウント）はUnixのパーミッションビットを持たないため、全ファイルが実行可能属性として見え `git status` が誤って「変更あり」と表示することがある。これを防ぐため、このリポジトリ限定で以下を設定する。

```bash
git -C <移動先> config core.fileMode false
git -C <移動先> status
```

### Step 5: 結果報告

- シンボリックリンクの内容（`ls -la <移動元>` で `->` の先を確認）
- `git status` がクリーンであること（Gitリポジトリの場合）
- Obsidian等のアプリ側で開き直しが必要な場合はその旨を伝える

## 注意事項

- `mv` はディレクトリ丸ごとの移動であり、大きなリポジトリや大量のファイルがある場合は時間がかかることがある
- 移動は一度きりの操作であり、元の場所には戻せないわけではない（逆の手順で戻せる）が、実行前に必ずパスをユーザーに復唱して確認すること
- `.obsidian/workspace.json` 等のローカル状態ファイルは環境依存のため、Gitで管理する場合は `.gitignore` への追加を別途検討する
